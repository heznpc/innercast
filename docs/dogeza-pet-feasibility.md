# 도게자 펫: 요구사항과 검증 현황

2026-09-18 기준. 아래 요구사항은 현재 사용자 발언과 연결된 작업의 사용자
정정을 요약한 것입니다. 과거 AI의 제안·사과·가능하다는 답변은 구현 근거로
취급하지 않습니다.

## 요청한 결과

사용자가 AI에게 화났다는 신호에 **스스로 도게자하는 내장 펫 하나**를 만들고,
**그 캐릭터를 서브에이전트로도 호출**할 수 있어야 합니다. 감지 비용을 먼저
밝혀야 하며, 원래 문제였던 사과 메시지와 토큰 낭비를 늘리는 설계를 기본값으로
채택하지 않습니다. 캐릭터의 이름·외형은 아직 정하지 않았습니다.

| 조건 | 출처·성격 | 현재 근거와 상태 | 실제 인수 검증 |
| --- | --- | --- | --- |
| 앱의 내장 펫에 추가 | 사용자 요구 | 설치 규격 확인. Innercast 펫 설치는 미검증 | 앱 펫 목록과 화면에서 설치한 캐릭터 확인 |

## 확인한 근거

### 펫 규격과 동작

공식 [Pets 문서](https://learn.chatgpt.com/docs/pets)를 직접 조회했습니다.
커스텀 펫은 외형을 바꾸며, 데스크톱 펫은 대화 상태를 표시합니다. 여러 대화가
있으면 우선순위에 따라 상태를 표시하므로 특정 서브에이전트의 몸이라고 가정할
수 없습니다. 웹 업로드와 데스크톱 제작 규격도 서로 구분해야 합니다.

설치된 ChatGPT **26.911.61220, build 9647**의 번들 자료를 확인했습니다.

- `hatch-pet/references/codex-pet-contract.md`: 데스크톱 v2 패키지는
  `pet.json`과 투명 스프라이트이며, 1536×2288, 8열×11행입니다.
- `hatch-pet/references/animation-rows.md`: 기본 작업 상태와 시선 방향의
  프레임 구성이 정의돼 있습니다. 프레임에 도게자를 그리는 것과 이를 사용자
  항의에 연결하는 것은 별도의 구현입니다.
- `avatar-overlay-native-page-4ffe9f352282.js`: 알림 상태에서 `running`,
  `failed`, `waiting`, `review` 등으로 매핑하는 코드를 확인했습니다.
- `avatar-overlay-debug-state-6ab16450350a.js`: 창 경계 표시용 설정이며,
  확인한 파일에서는 임의의 펫 동작을 재생하는 제어기가 아니었습니다.

문서 검색과 위 파일의 제한된 조사에서는 외부 프로그램이 특정 내장 펫에
도게자를 지시하는 공개 제어 경로를 찾지 못했습니다. **이는 경로 미확보라는
결론이며, 모든 내부 경로를 조사해 불가능을 증명한 것은 아닙니다.** 앱을
수정하거나 임의의 내부 메시지를 주입하는 검증도 하지 않았습니다.

### 입력 수신과 비용

공식 [UserPromptSubmit 훅](https://learn.chatgpt.com/docs/hooks#userpromptsubmit)은
제출할 사용자 프롬프트를 전달합니다. Codex 작업에서 감지기의 입력으로 사용할
후보입니다. 입력 중인 키보드 내용을 관찰하거나 모든 ChatGPT 대화를 읽는다는
뜻은 아닙니다. 실제 앱에서 이 훅을 설치·실행하는 시험은 아직 하지 않았습니다.

로컬 규칙 감지는 추가 LLM 추론을 요구하지 않습니다. 반면 메인 모델에 판단을
맡기거나 동작 도구를 호출하게 하면 추가 지침·추론·출력 사용이 생길 수 있습니다.
별도 API 요청이 없다는 이유로 무료라고 설명하면 안 됩니다. 로컬 규칙의 실제
오탐·누락률, 모델 경로의 추가 사용량 모두 측정하지 않았습니다. 펫 그림 제작
비용과 이후 반응의 실행 비용도 별도입니다.

### 서브에이전트

공식 [커스텀 에이전트 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)와
기존 `innercast/adapters/codex/agents/forge.toml`을 확인했습니다. 사용자 정의
역할 등록은 지원됩니다. 그러나 Forge의 기존 설정이 있다고 해서 요청한 도게자
펫이 구현되거나 같은 런타임 상태를 공유하는 것은 아닙니다.

## 아직 실행하지 않은 기능 시험

아래는 **예정된 검증 항목이며 통과한 테스트가 아닙니다.**

- AI 답변에 대한 직접적인 항의에 반응하는지.
- 욕설이 포함된 인용문·코드·외부 사건 이야기에는 불필요하게 반응하지 않는지.
- 욕설 없는 항의, 반복 정정, 부정 표현을 어떻게 처리하는지.
- 중복 이벤트가 들어와도 도게자를 계속 처음부터 재생하지 않는지.
- 다른 대화의 입력이 현재 캐릭터에 잘못 적용되지 않는지.
- 실제 내장 펫이 조작 없이 도게자하고 원래 상태로 복귀하는지.
- 같은 캐릭터의 서브에이전트가 실행되고 결과를 반환하는지.
- 반응 감지·재생 때문에 모델 호출이나 추가 문맥 주입이 발생하지 않는지.

기존 27개 테스트는 하네스 구조, 에이전트 컴파일러, 웹 프롬프트 등을 검사합니다.
**자동 도게자·감정 신호 감지·내장 펫 제어를 검사하지 않습니다.**

## 바로잡은 제안과 다음 검증

- 첫 캐릭터를 Forge나 작업용 로봇으로 정한 것은 AI의 임의 제안이었습니다.
  첫 시제품의 요구는 자동 도게자이며 이름·외형은 미정입니다.
- `innercast_react(...)`는 제안한 인터페이스 이름일 뿐, 현재 존재하는 도구나
  내장 펫에서 작동이 확인된 API가 아닙니다.
- `failed` 프레임을 도게자로 그려도 사용자 항의 감지가 연결되지는 않습니다.
- 별도 웹 캐릭터나 오버레이의 성공은 내장 펫 요구의 성공 증거가 아닙니다.

우선 검증할 것은 **실제 내장 펫의 동작을 외부의 한 번짜리 신호로 선택할 수
있는 경로**입니다. 지원되는 연결을 찾으면 펫에서 재생을 확인하고, 이후 감지와
연결합니다. 경로를 확보하지 못하면 그 제약을 그대로 보고해야 하며, 사용자의
요구를 다른 화면으로 바꾸거나 완성된 시나리오처럼 설명하지 않습니다.
